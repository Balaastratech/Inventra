# Project instructions — Vitrious/Inventra

## Never narrow scope without asking first

If you say you will do a large or multi-part task (e.g. "run all 30+ scenarios," "test everything in X"), do exactly that — every part of it. Do not quietly drop, defer, or de-prioritize part of it partway through, even for a good reason (found a bug, ran long, got distracted by a related request).

If something genuinely needs to be cut, paused, or reordered:
- Say so explicitly, at the moment you decide it, in the same message where you're about to skip it.
- Name exactly what is being deferred and why.
- Wait for the user to confirm before treating anything as out of scope.

Do not let a task silently become "done" in your own reporting when part of it was skipped. If you're unsure whether something counts as done, say what's actually done and what isn't, rather than defaulting to a summary that implies completion.

This applies to test runs, refactors, migrations, or any other task described as covering multiple items — the default is full scope, not partial scope with silent gaps.
